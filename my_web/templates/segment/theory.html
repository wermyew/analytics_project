Segment Tree (дерево отрезков)

Структура данных для быстрых запросов «сумма на отрезке» с возможностью обновлять отдельные элементы. В нашем случае — сумма total за диапазон заказов, упорядоченных по created_at.

Как устроено

  1. Массив значений a[0..n-1] (у нас — total, отсортированный по дате).
  2. Дерево — массив tree[1..4n]. Каждый узел хранит сумму своего подотрезка.
  3. Корень tree[1] — сумма всего массива.
  4. Лист tree[v] — одно значение a[i].
  5. Внутренний узел = сумма двух детей: tree[v] = tree[2v] + tree[2v+1].

Сложности

Операция Naive Segment Tree
Построение—O(n)
Сумма на отрезке [l, r]O(r − l + 1)O(log n)
Обновление a[pos] = valueO(1)O(log n)
ПамятьO(1)O(4n)

Naive-сумма выигрывает на очень коротких диапазонах и на разовых запросах. Segment Tree выигрывает при многих запросах и обновлениях: O(log n) на каждую операцию вместо O(n).

Что мы построили на датасете

  • Массив total, отсортированный по created_at (120 000 значений).
  • Дерево размером 4n = 480 000 узлов.
  • query(l, r) — сумма total для заказов с l-го по r-й.
  • update(pos, value) — меняет total одного заказа и пересчитывает предков.
  • Важно: records, values и tree всегда синхронны — обновление идёт только через SegmentTreeIndex.update.
